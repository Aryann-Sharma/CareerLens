# Learning guides and roadmaps

Select a tag under **Skills to build** to open a learning guide. Each of the 18
catalog technologies has a goal, three practice milestones, a project idea, and
a link to documentation or a learning resource maintained by the relevant
project. Links were checked on 2026-10-13. The reading resources are free;
optional hosting, services, certificates, or product plans can cost extra.

The guides are short starting points, not complete courses or evidence of
proficiency. Their exercises and ordering are curated in
`backend/app/services/learning.py`. They are not generated by a model. Unknown
phrases get a clearly labelled practice template without invented course links.
Close spellings such as `Pythom` offer a choice to view Python's guide, without
renaming the analysis skill. Case-only differences and known aliases open the
same guide directly.

## Build a plan

After analyzing, use **Your learning roadmap** below the results. The default
plan uses the missing skills from that analysis. Foundations appear before
skills that use them; for example, the React route includes JavaScript and CSS,
with HTML earlier in the sequence. This is one suggested learning route, not a
claim that every dependency is universally required.

If a description only says “good at programming,” choose an optional direction:

- Web development: browser foundations — HTML, CSS, JavaScript, Git.
- Application development with Java — Java, SQL, Git.
- Web services with Python — Python, SQL, FastAPI, Git.
- Data and modelling foundations — Python, SQL, Machine Learning, Git.
- Relational databases — SQL, PostgreSQL, Git.
- Containers and infrastructure — Linux, Docker, Git.

These are deliberately small starter paths. They do not cover every occupation
or prescribe every technology in that occupation. The user chooses a direction;
the app does not assume a programming language from a vague description.
The separate [role-classification experiment](role-experiment.md) was not
accurate enough to use for automatic direction selection.

Each step says **From your analysis**, **Suggested foundation**, or **Suggested
for your direction**. Job-derived reasons take precedence if a skill appears in
more than one group. Suggestions never enter the job's extracted skill list or
change its fit score.

Known profile skills are omitted using case-insensitive exact aliases. Longer
experience descriptions are not interpreted again by the planner. Skip a
foundation if it repeats knowledge you already have. The plan uses the analyzed
snapshot, so edits to the input form only take effect after another analysis.

Check off practice milestones and use **Download checklist** to keep a text
copy with projects, progress, and links. Progress is held in page memory only,
including for signed-in accounts. Refreshing, logging out, rebuilding, or
successfully analyzing again clears it. Saving an analysis does not save a
roadmap. No browser storage or new database table is used.

## Review before planning

**Edit skills** beside the result heading opens the editor directly below the
spelling checks. Accepting a spelling suggestion brings the editor into view.
Review the wording and choose **Update analysis** to recalculate. The source
description sits below the update button, so it does not push editing controls
out of the way.

## API

All three routes are public and do not store data:

| Route | Purpose |
| --- | --- |
| `GET /api/learning/directions` | List the six curated direction IDs and starter skills |
| `GET /api/learning/guide?skill=Java` | Return a guide or an explicit unsupported-phrase fallback |
| `POST /api/learning/plan` | Order missing skills, foundations, and an optional direction |

Example plan request:

```json
{
  "missing_skills": ["React", "SQL"],
  "user_skills": ["JavaScript", "HTML"],
  "direction": "web"
}
```

Skill lists allow up to 200 entries, each at most 100 characters after trimming.
Blank entries and case duplicates are removed. Unknown direction IDs and extra
fields are rejected. A guide query accepts 1–100 nonblank characters. Guide and
plan responses use `Cache-Control: no-store` because they can contain submitted
skill phrases. The server never follows user-provided URLs.

The browser renders text without HTML interpretation, uses native modal dialogs
for keyboard navigation, and discards late responses after a new analysis or
logout. Resource links open in a separate tab with `noopener noreferrer`.

## Resource maintenance

Guides link to MDN, dev.java, Python.org, React, TypeScript, Node.js, PostgreSQL,
Pro Git, Ubuntu, Docker, Kubernetes, FastAPI, Django, scikit-learn, and the NLTK
book. The links and dates are stored alongside the guides. Recheck the destination
and guide assumptions before changing a resource; an HTTP success alone does not
establish that a course is suitable. No external resource request is made during
analysis or roadmap creation.
